# Alarm.com 2026.11.17

Stable release for the original `pyalarmdotcom/alarmdotcom` distribution.
This release brings the maintained v4-derived implementation back to the original
project without requiring original-repository users to switch repositories.

## Included

- Modern Home Assistant compatibility, bundled Python library, improved setup/MFA,
  state updates/reconnect handling, diagnostics, and regression tests.
- Alarm panels, locks, lights, garage doors/gates, thermostats, supported sensors,
  water valves, and camera live view through the bundled WebRTC card.
- Battery/trouble indicators, sensor bypass actions, light auto-off timers,
  activity history/unlock attribution, supported Z-Wave scene events, and
  temporary-user schedule read/write actions.
- A combined README preserving the original header, screenshots, safety guidance,
  and structure, with current device support, installation, known issues, and
  maintained feature documentation. Original contributor and license notices stay intact.
- Correct the declared configuration schema version to 5, matching the migration
  already included in the beta. Add migration checks for older entries and a
  second load, preserving entry identity, credentials and current arming options.
- Add Home Assistant 2026.11.2 to the existing November compatibility matrix and
  run package/camera-card validation on master as well as candidate pull requests.

## Upgrading

1. Create a full Home Assistant backup.
2. Update the existing Alarm.com repository installation through HACS/Marketplace.
3. Restart Home Assistant. Keep the existing Alarm.com configuration entry.
4. Complete reauthentication if requested, then check entities, arming profiles,
   automations and dashboards. Fully reload dashboards that use the camera card.

Two community reports confirm upgrades from the original v4 beta, including
arming/disarming on Home Assistant 2026.11.2. A direct live v3 upgrade remains
unverified. Automated configuration migration tests do not establish preservation
of every v3 entity or device-specific switch/select/number control. Restore the
full backup for rollback after migration, rather than only reinstalling old code.

Users already on `ibasebcast/ha-alarmdotcom` can stay on their current update
channel. Do not install both repository distributions in the same directory.
This release uses configuration schema 5. Switching back to a distribution or
release declaring an older schema requires a compatible update or a full backup
restore. The published `v2026.11.16b1` beta remains unchanged.

## Known limitations

See the [README known issues](../README.md#known-issues-and-limitations) for current
tracking links. Outstanding reports include slow sign-in/declined commands,
missing valves on some accounts, incorrect Moen Flo valve state, camera
classification and live-view limitations, continuous kiosk playback,
WebSocket interruptions and frequent camera-related login notifications.
The separate experimental sign-in branch is not included.

Camera discovery does not guarantee live video or snapshots for every model.
Water-meter readings, RGB control, full image-sensor UI, portal scene activation,
and complete user-access management are not implemented.

Please report upgrade results in
[issue #567](https://github.com/pyalarmdotcom/alarmdotcom/issues/567), keeping all
credentials, tokens, signed URLs, account/device identifiers and personal details
out of logs. Continue using official Alarm.com services for critical alerts.
